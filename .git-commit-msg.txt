fix: block prayer check-in on future days + homework tab infinite loop

Bug 1: Prayer check-in allowed on future days
- At Tuesday Isha time, tapping tomorrow's Fajr let you log it even though
  the prayer window hadn't started yet.
- Root cause: getPrayerWindowState compares currentMinutes (today's clock)
  against the target day's prayer times. For a future day, the comparison
  is meaningless — tomorrow's Fajr (5 AM) appears as "ended" because the
  current time (9 PM = 1260 min) is past 5 AM (300 min).
- Fix: Added isFutureDay check in PrayerCheckinPopup. If the viewed date
  is after today, windowState is forced to "before" so the popup shows
  "hasn't started yet" and blocks logging.

Bug 2: Bottom nav frozen after visiting Homework from daily view
- Tapping "Go to homework" from DayView navigates to /goals#homework.
  The Homework tab renders HomeworkTab → HomeworkClient. HomeworkClient
  has a useEffect that calls onHomeworkChange(homework) with deps
  [homework, onHomeworkChange]. HomeworkTab wrapped the callback in an
  inline arrow (new identity every render). The effect fired → setHomework
  in parent → re-render → new callback → effect fired again → infinite
  loop → frozen UI / dead bottom nav.
- Fix: Wrapped the HomeworkTab callback in useCallback (stable identity)
  AND removed onHomeworkChange from the effect deps in HomeworkClient
  (only depend on homework). Either fix alone stops the loop; both make
  it robust. Also exported HomeworkItem type for correct typing.
