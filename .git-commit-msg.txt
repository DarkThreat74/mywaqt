fix: event details field, short event height, bulk time-shift, remove tap-to-create

1. Event details field (new feature)
   - Added optional `details` text column to events table + migration 0022
   - Details shown under the title in the calendar as smaller, grayer text
   - Only shown when event duration >= 45 min (enough vertical room)
   - Added textarea input to the add/edit event form
   - Wired through all API routes: POST, PATCH, bulk PATCH, GET projections
   - Added to offline IndexedDB cache + all CalendarEvent interfaces

2. Short event box height (bug fix)
   - Events shorter than 30 min had boxes too small to read (min was 22px)
   - Increased minimum height to 44px so title + time are always visible
   - Box overlaps slightly into next slot but text remains readable

3. Bulk time-shift for recurring series (bug fix)
   - When editing a recurring event and choosing "apply to all", time
     changes (startAt/endAt) were silently dropped — the bulk PATCH only
     updated title/type/color/notify, not times.
   - Root cause: bulk PATCH explicitly excluded startAt/endAt with a comment
     saying "each occurrence has its own timestamp."
   - Fix: bulk PATCH now accepts startAt/endAt, computes the time delta
     from the first event, and shifts ALL events in the series by the same
     delta. Each occurrence keeps its calendar date; only the time-of-day
     changes. Duration changes are also applied.

4. Remove tap-to-create on calendar slots (UX change)
   - Removed the invisible tap-to-add zone buttons on every hour slot
   - Events can now only be created via the + FAB button
   - Prevents accidental event creation when scrolling/tapping the calendar
