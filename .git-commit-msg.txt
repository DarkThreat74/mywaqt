fix: FFmpeg filter chain fails on Vercel — add fallback chains

The full filter chain (highpass + lowpass + silenceremove + loudnorm)
was causing "Option not found" errors on Vercel's FFmpeg build. The
issue is that the Vercel Linux ffmpeg-static binary may not support
all filter options (likely leave_silence in silenceremove).

Fix: try three filter chains in order, use whichever works:

1. Full chain: highpass + lowpass + silenceremove + loudnorm
   (best quality — silence removal + broadcast loudness normalization)

2. No-silence chain: highpass + lowpass + loudnorm
   (if silenceremove/leave_silence isn't available — still gets
   volume normalization and frequency cleanup)

3. Volume-only chain: highpass + volume=2.0
   (fallback for minimal FFmpeg builds — simple 2x gain boost
   to ensure audio is audible)

Also switched from .audioFilter() to raw -af in .outputOptions()
for better compatibility, and added full stderr logging for each
chain attempt so we can see exactly what's happening on Vercel.
