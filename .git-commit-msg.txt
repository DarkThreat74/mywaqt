fix: offline talks download bar — opaque response was zeroing the size

Root cause: the stream endpoint returns a 307 redirect to a cross-origin
R2 URL. The Cache API follows the redirect and stores an opaque response.
response.clone().arrayBuffer() on an opaque response succeeds but returns
0 bytes, overwriting the correct metadata.fileSize with 0. The manifest
recorded size: 0 for every download, so the bar stayed at 0%.

- Only overwrite actualSize from the response if it's non-opaque and > 0
  bytes. Otherwise keep metadata.fileSize (from the DB, populated during
  upload/processing).
- Add backfillAudioCacheSizes() to fix existing manifest entries with
  size: 0 using the talk's DB fileSize. Called when the talks page loads.
- Settings page now also listens for pageshow (navigate-back refresh)
  in addition to the custom cache-changed event.
