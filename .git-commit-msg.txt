fix: offline talks download bar not updating after downloads

The settings page loaded audio cache info once on mount and never
refreshed. When the user downloaded talks on the talks page and
navigated back to settings, the bar showed stale data.

- Dispatch a "waqt:audio-cache-changed" custom event from
  saveAudioOffline and removeAudioOffline
- Settings page listens for this event and refreshes the cache info
  (count, size, progress bar) when it fires
- Also improved size calculation: if response.arrayBuffer() fails
  (streaming responses), fall back to content-length header before
  using the metadata fileSize
