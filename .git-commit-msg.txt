fix: restart button not working on stuck talks

The Restart button calls processTalk() which hits /api/admin/talks/process.
But if the talk is still in "processing" status, the process route's stale
check can reject it with 409 "Talk is already being processed" — even if
it's been stuck for 20+ minutes, because the stale window calculation
depends on maxDuration which changed between deployments.

Fix: Added a force-reprocess action to the admin talks API that
unconditionally resets the talk to "pending" status. processTalk() now
calls force-reprocess first if the talk is in "processing" status, then
calls the process route. This guarantees the restart always works
regardless of stale window timing.
