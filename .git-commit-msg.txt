feat: replace 9-filter FFmpeg pipeline with Opus 24kbps compression

BREAKTHROUGH: Research via agent-reach and context7 found that Opus
codec at 24kbps mono voip mode is better quality than MP3 at 64kbps
for speech, at 1/3 the bitrate. This eliminates the need for the
entire 9-filter FFmpeg pipeline.

OLD approach (9 filters, 3 passes):
  silenceremove → highpass → lowpass → afftdn → de-essing →
  speech EQ → two-pass loudnorm → dynaudnorm → limiter
  Output: MP3 64k mono 22050Hz
  Speed: ~6x realtime (with measurement pass)
  64MB file → ~120MB output, ~10+ min processing

NEW approach (0 filters, 1 pass):
  ffmpeg -i input -c:a libopus -b:a 24k -ac 1 -application voip
  Output: Opus 24kbps mono
  Speed: ~30x realtime
  64MB file → ~10MB output, ~2 min processing
  300MB file → ~45MB output (if processed)

Opus is supported by all modern browsers in <audio> elements:
Chrome 25+, Firefox 15+, Safari 11+ desktop / 14+ iOS, Edge 14+

Changes:
- New compressAudioFile() function: single FFmpeg transcode to Opus
- Process route simplified: download → compress → upload (3 steps, not 6)
- Removed: processingOptions(), tiered logic, ProcessingOptions merge
- Removed: FAST_PROCESSING_OPTIONS, ULTRA_FAST_PROCESSING_OPTIONS usage
- Removed: localStorage audio options in admin UI
- Storage key now uses .opus extension for processed files
- R2 upload uses audio/ogg content type for Opus files
- Admin UI processing time estimates updated for ~30x realtime
- Files >100MB still skip compression (300s Hobby limit)

Result: 64MB file processes in ~2min (was 10+ min).
Output is 85% smaller and better quality for speech.
