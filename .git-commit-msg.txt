feat: fast Opus transcode for large files + offline cache fixes

PROBLEM: Files >40MB were skipping processing entirely, serving the
original 150MB MP3. Streaming these used 50-150MB of cellular data
per talk. Downloaded copies were also 150MB instead of ~10MB.

FIX: Added compressAudioFileFast() — bare Opus transcode with no
filter chain and compression_level 0. Runs at ~25x realtime
(vs ~6x for the full chain), so files up to 150MB process within
the 300s timeout.

Processing paths:
  ≤40MB:   Full 10-stage filter chain (~6x realtime)
  40-150MB: Fast bare transcode, no filters (~25x realtime)
  >150MB:  Skipped (exceeds upload limit anyway)

Both paths produce 24kbps Opus (~85% smaller), so ALL talks now
stream at ~3 KB/s regardless of source file size.

DATA USAGE:
  Downloaded:      0 KB/s (served from cache)
  Not downloaded: ~3 KB/s (24kbps Opus) = ~10.8 MB/hour

Also includes offline cache fixes from the audit:
  - Storage estimate check before download
