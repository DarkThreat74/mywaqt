fix: calendar share code back to 6 chars, old tokens invalidated on regenerate

The calendar share link had reverted to a 32-char hex token (128-bit)
which is ugly and hard to share. Fixed to use the same 6-char
unambiguous alphabet as the prayer code (ABCDEFGHJKLMNPQRSTUVWXYZ23456789,
no I/O/0/1). 32^6 ≈ 1 billion possibilities — collision-resistant at
100k users with a DB uniqueness check.

- Share token generation now uses crypto.randomInt for unbiased selection
- All token validation sites accept both new 6-char codes and legacy
  32-char hex tokens (existing links don't break)
- Regenerating overwrites the old token in the DB, which deactivates
  the previous link immediately
- DB unique constraint on publicShareToken prevents overlap with
  another user's code
